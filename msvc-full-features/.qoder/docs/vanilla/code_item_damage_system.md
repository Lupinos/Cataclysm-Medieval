# C++ 物品伤害/破损等级系统调研

> 记录 CDDA 物品伤害字段的底层 C++ 存储、等级映射，以及它在 JSON `item_group` 中导致 NPC 装备破损一致性的数学原因。

---

## 1. 物品伤害的核心数据结构

在 CDDA C++ 源码中，物品的伤害和破损由以下字段和常数控制：

- **`itype::damage_scale`** (定义于 `src/itype.h`):
  ```cpp
  static constexpr int damage_scale = 1000;
  ```
  这是伤害级别的比例常数。每个逻辑破损等级（Level）对应 `1000` 个单位的实际伤害。
  
- **`itype::damage_max_`** (定义于 `src/itype.h`):
  ```cpp
  static constexpr int damage_max_ = 4000;
  ```
  最大实际伤害值。即一件物品在被完全摧毁前最多能承受 `4000` 点伤害（对应最高破损等级 4 级）。

- **`item::damage_`** (定义于 `src/item.h`):
  实际存储在物品实例上的伤害值，范围通常在 `[0, 4000]` 之间。

---

## 2. 破损级别映射算法 (Damage Level)

虽然实际伤害是 `[0, 4000]` 之间的连续整数，但游戏 UI 显示、数值惩罚等系统都将其折叠（Collapse）为离散的 **破损级别** (Damage Level)。

该映射在 `src/itype.cpp` 中的 `itype::damage_level(int damage)` 中实现：

```cpp
int itype::damage_level( int damage ) const
{
    if( damage == 0 ) {
        return 0; // 完好无损 (Level 0)
    }
    if( count_by_charges() ) {
        return 5;
    }
    return std::clamp( 1 + 4 * damage / damage_max(), 0, 5 );
}
```

按照此算法，将实际伤害值 `damage` 转换为 `damage_level` 的映射表如下：

| 实际伤害范围 (`damage`) | 整数除法计算 `1 + 4 * damage / 4000` | 破损级别 (`damage_level`) | 游戏 UI 显示 |
| :--- | :--- | :--- | :--- |
| `0` | 特判返回 `0` | **`0`** (完好) | (无标记) |
| `[1, 999]` | `1 + 0 = 1` | **`1`** (轻微破损) | `\` |
| `[1000, 1999]` | `1 + 1 = 2` | **`2`** (中度破损) | `\|` |
| `[2000, 2999]` | `1 + 2 = 3` | **`3`** (重度破损) | `\|\|` |
| `[3000, 3999]` | `1 + 3 = 4` | **`4`** (严重破损) | `\|\|\|` |
| `4000` | `1 + 4 = 5` | **`5`** (破损极致/濒临损毁) | `\|\|\|\|` |

> [!IMPORTANT]
> 注意在 `damage_level` 计算中：
> - 只要 `damage` 达到整千点（如 `1000`、`2000` 等），级别就会直接向上跳一级（如 `1000` 对应 Level 2，而非 Level 1）。
> - 这意味着 Level 1 只有 `[1, 999]` 共 999 个取值，而 Level 2 有 `[1000, 1999]` 共 1000 个取值。

## 3. JSON 物品组中伤害区间的解析与塌陷

当我们在 JSON 物品组（`item_group`）的条目中指定 `"damage": [min, max]` 时，系统在加载时会将其乘以 `damage_scale` (1000)：

```cpp
// src/item_factory.cpp:4902
use_modifier |= load_min_max( modifier.damage, obj, "damage" );
modifier.damage.first *= itype::damage_scale;
modifier.damage.second *= itype::damage_scale;
```

这意味着 JSON 中的伤害区间会发生如下转换：

- **`"damage": [ 1, 3 ]`** $\to$ 底层实际伤害范围 `[1000, 3000]`
- **`"damage": [ 0, 2 ]`** $\to$ 底层实际伤害范围 `[0, 2000]`
- **`"damage": [ 0, 1 ]`** $\to$ 底层实际伤害范围 `[0, 1000]`

当物品生成时，底层的 `rng(damage.first, damage.second)` 会在实际伤害范围内均匀随机抽取一个值。然而，**由于 `damage_level` 算法的区间折叠特性，这种均匀抽取会产生灾难性的概率塌陷：**

### A. Grunt 强盗的 `"damage": [ 1, 3 ]` 塌陷

实际抽取范围为 `rng(1000, 3000)`，共有 `2001` 个可能取值。

- **`damage` 落在 `[1000, 1999]`**: 对应 `damage_level = 2`。可能值有 `1000` 个。
  **概率：** $\frac{1000}{2001} \approx 49.975\%$
- **`damage` 落在 `[2000, 2999]`**: 对应 `damage_level = 3`。可能值有 `1000` 个。
  **概率：** $\frac{1000}{2001} \approx 49.975\%$
- **`damage` 刚好为 `3000`**: 对应 `damage_level = 4`。可能值有 `1` 个。
  **概率：** $\frac{1}{2001} \approx 0.05\%$

> [!WARNING]
> **结论**：Grunt 的任何一件装备，在视觉上**几乎必然只有 Level 2 (中度破损) 或 Level 3 (重度破损) 两种可能，概率几乎各为 50%**。
>
> 即使为 Grunt 独立抽取 3 件装备，这 3 件装备都随机落入**完全相同**的破损等级（比如全为 2 级，或者全为 3 级）的概率为：
> $$(0.5)^3 + (0.5)^3 = 12.5\% + 12.5\% = 25.0\%$$
>
> 也就是说，**每 4 个 Grunt 强盗中，就会有 1 个强盗身上的所有装备破损等级完全一致！** 这种高概率导致玩家很容易观察到“破损程度完全一致”的现象。

---

### B. Chief 头领的 `"damage": [ 0, 1 ]` 极度塌陷

实际抽取范围为 `rng(0, 1000)`，共有 `1001` 个可能取值。

- **`damage = 0`**: 对应 `damage_level = 0` (完好)。可能值 `1` 个。
  **概率：** $\frac{1}{1001} \approx 0.1\%$
- **`damage` 落在 `[1, 999]`**: 对应 `damage_level = 1` (轻度破损 `\`)。可能值 `999` 个。
  **概率：** $\frac{999}{1001} \approx 99.8\%$
- **`damage = 1000`**: 对应 `damage_level = 2` (中度破损 `\|`)。可能值 `1` 个。
  **概率：** $\frac{1}{1001} \approx 0.1\%$

> [!CAUTION]
> **结论**：Chief 头领的任何一件装备，**有高达 99.8% 的概率被直接锁定在 Level 1 (轻度破损)！**
>
> 如果 Chief 身上穿着 7 件装备（内衬、内甲、外甲、裤子、头盔、手套、鞋子），**所有 7 件装备全部被锁定在 Level 1 的概率为：**
> $$(99.8\%)^7 \approx 98.6\%$$
>
> 也就是说，**98.6% 的 Chief 强盗在生成时，其身上的所有装备看起来全部都是整整齐齐的 1 级破损 (`\`)！** 这根本不是真正的随机，而是底层除法折叠导致的必然结果。

---

### C. Veteran 强盗的 `"damage": [ 0, 2 ]` 塌陷

实际抽取范围为 `rng(0, 2000)`，共有 `2001` 个可能取值。

- **`damage = 0`**: 对应 `damage_level = 0`。概率 $\approx 0.05\%$
- **`damage` 落在 `[1, 999]`**: 对应 `damage_level = 1`。概率 $\approx 49.9\%$
- **`damage` 落在 `[1000, 1999]`**: 对应 `damage_level = 2`。概率 $\approx 50.0\%$
- **`damage = 2000`**: 对应 `damage_level = 3`。概率 $\approx 0.05\%$

> [!NOTE]
> 同样塌陷为 **Level 1** 与 **Level 2** 的 50/50 抛硬币，导致极高的一致性概率（5件套全部一致的概率约为 6.25%，4件套一致的概率为 12.5%）。

---

## 4. 优化建议：如何重获真正的随机多样性？

要想打破这种概率塌陷，让同一个 NPC 身上的装备呈现参差不齐、生动真实的破损状态，我们可以通过**微调 JSON 中的伤害区间上限和下限**来实现。

### 方案 1：向后兼容的轻微微调 (推荐)

通过将下限拉低到 `0` 并提升上限，可以让概率在多个离散级别之间均匀分布：

1. **Grunt (小兵)**: 将 `"damage": [ 1, 3 ]` 改为 **`"damage": [ 0, 3 ]`**
   - 实际抽取范围 `[0, 3000]`
   - Level 0 (完好) 概率 $\approx 0.03\%$
   - Level 1 (轻度) 概率 $\approx 33.3\%$
   - Level 2 (中度) 概率 $\approx 33.3\%$
   - Level 3 (重度) 概率 $\approx 33.3\%$
   - Level 4 (严重) 概率 $\approx 0.03\%$
   - **效果：** 装备会完美、均匀地混合 1级、2级、3级 破损，3件套全部一致的概率降低至 $\approx 11\%$。

2. **Veteran (精英)**: 将 `"damage": [ 0, 2 ]` 改为 **`"damage": [ 0, 3 ]`** (或者保留 `[0, 2]`，但在武器上使用 `[0, 3]` 来区分)
   - 增加 3级 重度破损的混入，使得 1、2、3 级破损更加丰富。

3. **Chief (首领)**: 将 `"damage": [ 0, 1 ]` 改为 **`"damage": [ 0, 2 ]`**
   - 实际抽取范围 `[0, 2000]`
   - 让装备在 Level 1 (轻度) 和 Level 2 (中度) 之间有 50/50 的均匀分布，或者部分装备保持 `[0, 1]`，而另一些高磨损部位（如鞋子、盾牌）使用 `[0, 2]`，彻底打破整齐划一的“1级破损”死锁。
